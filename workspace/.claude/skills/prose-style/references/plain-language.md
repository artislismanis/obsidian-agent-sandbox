# Plain language

Use the word a non-technical reader would use. If a word has a shorter,
clearer equivalent, switch.

## Nominalisations

Verbs hiding inside noun phrases. Liberate the verb.

| Avoid | Use |
| --- | --- |
| make a decision | decide |
| give consideration to | consider |
| reach an agreement | agree |
| conduct an investigation | investigate |
| provide a recommendation | recommend |
| perform an analysis | analyse |
| make an assumption | assume |
| have a conversation | talk |
| do a review | review |
| the implementation of X | implementing X |
| the creation of X | creating X |
| the deletion of X | deleting X |
| the discussion of X | discussing X |
| be responsible for routing | route |
| is in charge of validation | validates |

**Test:** find the verb buried in the noun phrase. Put it back to work.

## When jargon is fine

Domain terms that are precise and the reader needs: OAuth, OOM, P99,
idempotent, deadlock, mutex, kernel, k8s, RAG, embedding,
quorum. These are not jargon; they are the right word.

Define on first use when the document might reach a non-technical
reader. Otherwise assume the reader knows.

## When to add to this list

A swap belongs here when:

- The long version has appeared in this project's prose, AND
- The short version captures the same meaning, AND
- A reader without a thesaurus would prefer the short version.

Keep tables roughly alphabetical within each section.
